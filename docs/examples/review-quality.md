# 검수 보고서 작성 예제

아래는 보고서 서술 방식을 보여 주는 가상의 페이지 조회 사례입니다. 경로, 요청, 응답 및 판정은 설명용입니다.

| 항목 | 설명이 부족한 사례 | 검토에 필요한 설명을 갖춘 사례 |
| --- | --- | --- |
| 문제와 재현 | “두 번째 페이지가 잘못 나왔다.” | “`list_items(limit=2, cursor=<첫 페이지가 반환한 값>)`이 첫 페이지 항목을 다시 반환했다. 같은 커서로 독립 HTTP를 호출하면 200과 다음 두 항목을 반환했다. 기대 동작은 커서를 이어받아 다음 페이지부터 보여 주는 것이다. 로컬 증거에서 두 요청과 항목 순서를 확인할 수 있다.” |
| 원인과 영향 | “페이지 요청 함수에 문제가 있었다.” | “`src/tools/list.ts`의 `listItems`는 입력에서 커서를 읽지만 요청 객체를 조립할 때 `limit`만 넘긴다. 서버는 커서 없는 요청으로 해석해 첫 페이지를 반환한다. 호출자는 뒷부분을 읽기 위해 반복 호출해도 같은 항목을 받으므로 전체 목록을 수집하지 못할 수 있다.” |
| 변경과 대안 | “페이지 요청을 고쳤으므로 반영한다.” | “변경 범위는 입력 커서를 기존 요청에 전달하는 부분이다. 핵심 전후 코드에서 요청 필드가 조립되는 위치를 확인할 수 있다. 클라이언트에서 전체 목록을 받은 뒤 나누는 방식도 검토했지만 네트워크 비용이 커지고 서버의 커서 의미를 복제해야 한다. 기존 서버 계약을 사용하는 편이 첫 페이지 호출과의 호환성을 유지한다.” |
| 검증과 반영 근거 | “테스트가 통과했다.” | “동일한 테스트 데이터에서 기준은 첫 페이지를 반복했고 후보는 독립 HTTP와 항목 순서가 일치했다. 커서 없는 호출과 마지막 페이지에 대한 회귀 검사도 통과했다. 목록 완전성을 회복한다는 근거로 반영을 권장한다. 통제 실험에서는 페이지 이동만 확인했으며, 서비스에서 데이터가 동시에 변경될 때의 커서 동작은 미검증이다.” |

실제 요청이 오류 응답으로 끝난 경우에는 비식별 오류 문구와 독립 HTTP 상태를 함께 적습니다. 비교할 MCP 값이 없다면 그 사실을 표시하고, 독립 HTTP 표본은 공개 권한 범위에서 제시합니다. 실제 보고서에는 관련 파일과 함수, 핵심 전후 코드, 실행 ID 또는 로컬 증거 포인터를 추가합니다.
